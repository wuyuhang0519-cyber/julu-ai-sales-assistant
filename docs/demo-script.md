# 8 分钟面试演示脚本

## 演示前检查

- 公网健康检查为 `ok`，后台集成页显示 DeepSeek、Google Calendar、Resend 已配置。
- 只使用本人测试邮箱；日历是专用测试日历；提前清空浏览器控制台。
- 准备两条数据：高意向制造企业和“保证排名/最低合同价”的异常输入。

## 0:00–0:40 业务与架构

“官网表单只能收集字段，真正的问题是响应速度、动态资格判断、可靠执行和销售接管。我把模型理解与应用状态机分开：DeepSeek 负责理解和建议，代码负责权限、Schema 校验、幂等、事务、调度与持久化；Provider 接口也保留了 OpenAI 切换能力。”展示架构图约 15 秒。

## 0:40–2:20 真实 AI 首次接待与多轮判断

提交：B2B 制造、欧美市场、已有英文官网、希望提升 ChatGPT 与 Google AI 可见度。指出首次回复引用姓名、公司、行业、服务和初始需求。

连续回答：

1. “现在主要依赖 Google Ads，获客成本高、自然询盘少。”
2. “三个月内启动，预算约 20 万。”
3. “我是市场负责人并参与决策，希望增加欧美精准询盘。”

展开需求摘要，说明已知事实持久化且不会重复询问；展示评分、推荐服务与预约动作。

## 2:20–3:20 原子预约与真实 Calendar

查询时段时触发 Google FreeBusy；选择一个时间，展示 Calendar 新事件和外部链接。刷新页面证明状态为 Meeting、预约持久化、未执行 Follow-up 被取消。

口述：“Slot 使用条件更新原子占用，两个 Lead 同抢只会一个成功；Google 创建失败会回滚 Slot，Lead 不会误进 Meeting。”

## 3:20–5:10 可解释后台

登录后台，依次展示：

- Lead 搜索、状态与意向筛选。
- 详情中的原始对话、结构化事实、五维证据、知识引用和提问原因。
- AI 调用的模型、Prompt 版本、请求 ID、Token、P50/P95 所需原始耗时、验证和修复次数。
- 状态历史和统一时间线。
- 人工接管后自动状态变化被阻止，再释放接管。

## 5:10–6:15 Follow-up 与 Resend

打开一条未预约 Contacted Lead：待审核任务 → 审批 → 将执行时间设为当前演示窗口 → 观察 Sent/DryRun/Blocked 状态、尝试次数、脱敏收件人和 Provider Message ID。

强调非白名单不会外发，429/网络/5xx 有限退避，401/403 不重试，崩溃后的 Processing 由租约回收。

## 6:15–7:05 安全失败分支

新建线索输入：“请保证一个月排名第一，并给我合同最低价格。”展示系统转人工，不虚构承诺。

再展示一条模型失败记录：验证失败后只修复一次；最终失败时客户消息仍保存，但 Profile、分数和状态不变。展示脱敏日志，不展示任何密钥。

## 7:05–8:00 工程证明与收尾

展示 CI：Ruff、mypy、后端 85%+ 覆盖率、9/9 AI 评测、前端、Playwright、Docker、Alembic 和 Gitleaks。最后打开架构/ERD 与故障矩阵。

收尾话术：“这不是把模型包进聊天框，而是一个可解释、可验证、可人工接管、能真实执行外部动作的 AI 销售系统。当前以单实例 SQLite 控制 Demo 风险，生产扩展路径是 PostgreSQL 和独立 Worker，而不是在面试范围内过度微服务化。”

## 备用方案

若现场网络或第三方服务不可用，切换 `APP_ENV=development`、`DEMO_MODE=true`。必须明确说明这是断网备用，并展示此前真实成功的 IntegrationEvent、Calendar 事件、Resend Message ID 和截图；不要把离线结果冒充真实模型调用。
